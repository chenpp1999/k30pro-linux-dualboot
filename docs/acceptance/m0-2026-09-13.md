## 前置条件

- bootloader 已解锁（`fastboot getvar unlocked` → `yes`）；
- 产物 sha256 与上表一致；initramfs 内 `/init` 为 LF（断言：CRLF shebang 0 处）；
- 宿主（Windows 11）已装 fastboot 驱动；NCM 网卡由系统内置驱动自动绑定
  （RNDIS 在 24H2+ 已移除，见 issue #2）。

## 执行步骤（终轮）

1. `fastboot boot boot-m0.img`；
2. 内核启动（~18s），initramfs `init`：清 BCB → NCM gadget → dropbear →
   **m0-display 常驻接管显示**（后台）；
3. 宿主出现 `UsbNcm Host Device` → `172.16.42.2/24`；
4. `ping 172.16.42.1` → `ssh root@172.16.42.1`（密码见 runbook）；
5. 采集 dmesg / 输入设备 / 触摸事件；
6. `reboot -f` 回归 Android。

## 遗留问题（转 M1）

1. `m0-display` 显示的是测试色条（KMS 接管的最小验证）；完整 UI（seatd/Weston、
   固件挂载、显示接管流程）按 D80 基线在 M1 落地。
2. lmi 上普通 `reboot` 无效，用 `reboot -f` 或长按电源（runbook 已更新）。
3. 首轮失败链条（均已修复）：方式 B 失败→BCB 残留（#1）→ init CRLF→退出 127
   （#3）→ RNDIS 无驱动（#2）→ 黑屏无接管（#4）。
