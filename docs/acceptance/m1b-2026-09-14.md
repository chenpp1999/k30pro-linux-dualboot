## 关键发现（实测根因，均已在仓库修复）

1. **dropbear 无法启动**：Alpine 的 `/etc/init.d/dropbear` 依赖为 `need net`，
   而 rootfs 未启用 `networking` → 依赖链拒绝
   （`ERROR: cannot start dropbear as networking would not start`）。
   修复：initd 改 `use net`；`etc/conf.d/dropbear` 增补 `-P /run/dropbear.pid`
   使 stop/status 正常工作。
2. **wpa_supplicant 打印 usage 即退出**：Alpine 的 wpa_supplicant 未编译
   `CONFIG_DEBUG_FILE`，不支持 `-f <log>` 选项；`lmi-wifi-start` 原调用带 `-f`
   → 直接 usage+rc=1 → 无 supplicant、无 DHCP（WiFi `status=failed`）。
   修复：改为 stderr 追加重定向 `2>>/var/log/wpa_supplicant.log`。
3. **离线修补镜像的 journal 陷阱**：从分区 dump 的 ext4 若带未回放 journal
   （强制重启/非正常卸载），用 debugfs 直写后，随后任何 `e2fsck -fy` 会先回放
   journal，把刚写入的内容**静默回滚**（实测 `conf.d` 被回滚为 190 B 截断文件）。
   正确顺序：先 `e2fsck -fy` 回放 → debugfs 写入 → `e2fsck -fy` 修计数 →
   dump+cmp 校验。已固化为 `tools/m1/patch-rootfs-image.sh`。
