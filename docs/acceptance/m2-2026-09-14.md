## T1-03：recovery 引导失败根因与修复（本轮关键发现）

- **现象**：写入 BCB `boot-recovery` 后普通重启、以及 `fastboot reboot recovery`，
  设备均落入 **fastboot**（与 issue #1 记录的 M0 方式 B 失败模式一致；此前误判为 init CRLF）。
- **ABL/UEFI 日志证据**（`/dev/logfs/UefiLog1.txt`，失败那次）：

  ```
  Booting Into Recovery Mode
  avb_slot_verify.c:680: ERROR: recovery: Public key used to sign data rejected.
  VB2: Authenticate complete! boot state is: orange     # AVB 失败非致命（已解锁）
  Dtbo hdr magic mismatch 52444E41, with D7B7AB1E       # 52444E41 = "ANDR"（镜像开头 ANDROID!）
  DTB offset is incorrect, kernel image does not have appended DTB
  Error: Device Tree blob not found
  Launching fastboot
  ```

- **根因**：ABL 的 recovery 引导路径从 boot image header 的 `recovery_dtbo`
  字段读取 DTBO 表；`boot-m0.img`/`boot-m1b-v6.img` 该字段为 0（`mkbootimg
  --header_version 2` 不会自动写入），ABL 于是在偏移 0 处读到 `ANDROID!` 魔数，
  判定无 DTB → 回落 fastboot。对照：`recovery-twrp.img`（可正常从 recovery 启动）
  的 `recovery_dtbo_size=12,330,818`。
- **修复**：打包时显式传入 `--recovery_dtbo`，内容取**本机当前 dtbo 表**
  （`dtbo-new.img`，487,424 B，sha256 `32e9ba4f…`，含 aw8697 disabled 修改）。
  已固化到 `tools/m1/build-m1b-image.sh --recovery-dtbo`；
  另修复 Debian 版 `mkbootimg` 的真除 bug（`get_number_of_pages` 的 `/` → `//`，
  否则 `pack('Q')` 报 struct.error）。
- **修复验证**：v7 从 recovery 启动 → UEFI 日志 `Apply Overlay total time: 689 ms`，
  无 Dtbo/DTB 报错；Linux 正常启动且 ledger 记录 `bcb=626f6f742d7265636f76657279…`
  （`boot-recovery`）→ 证明 **ABL 未清 BCB、由 Linux init 清除**（T1-03 结论）。

## T2-04 中断电明细

- 方式：`to-linux --no-reboot` 后台执行，0.5 s 后 SIGKILL（等价于写盘阶段断电）。
- 结果：`rc=137`（KILLED）于 `writing … -> recovery` 阶段；**BCB 仍为空**；
  recovery 首字节为部分写入的 `ANDROID!`。
- 随后普通重启 → Android（45 s 就绪），BCB 保持为空。符合设计
  「先镜像、后 BCB；写镜像阶段断电 → 重启回 Android」。

## T2-03 自愈明细

- Linux 内以 `dd` 向 `misc`（`/dev/sda11`）写入 BCB `boot-recovery` 并校验；
  `reboot` 后 bootloader 再次进入 recovery（Linux），ledger 记录
  `boot=16 … bcb=626f6f742d7265636f76657279…`；init 清除 BCB（读回全零），
  随后重启回 Android。

## TWRP 恢复演练明细

- `restore-twrp`：备份哈希 `86e4bf8d…` 预检通过 → 写入 → 全量回读校验通过。
- `reboot recovery` → TWRP `3.7.1_12-RedmiK30Pro_v9.2_A15` 正常启动（adb state
  `recovery`）→ `adb reboot` 回 Android。
