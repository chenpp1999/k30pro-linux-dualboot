# UX 调研：Weston 14 下的中文输入（OSK / IME）选型

- 日期：2026-09-15
- 目标设备：Redmi K30 Pro (lmi)，Alpine 3.23 aarch64 (musl, OpenRC)，Weston 14.0.2 (pixman, DRM)，540x1200 逻辑分辨率 @scale 2，触摸屏，rootfs ~1.4GB
- 现状：自补丁 weston-keyboard 已可用（符号层、45px 键宽、立即提交、Backspace keysym 回退），无中文；weston-terminal 已补 text-input-v1（客户端侧）
- 标记约定：**[验证]** 有来源可查；**[推断]** 基于证据的工程判断，未直接实测

---

## 0. 结论摘要（先看这里）

1. **没有"小体积、直接移植、且协议匹配 Weston 14"的中文 OSK。** 唯一现成的、协议匹配且有中文的开源键盘是 **Maliit（Alpine 3.23 已打包 maliit-keyboard，依赖里已含 libpinyin）**，代价是 Qt5 全家桶（约 250–350MiB 安装体积）且中文插件多年少人维护。
2. **fcitx5 支持 Weston 的 `zwp_input_method_v1`（官方 wiki 明确给出 weston.ini 配置）**，但它是输入法框架、不是屏幕键盘；Weston 每 seat 只允许 **一个** IM 客户端绑定，所以 fcitx5 会顶掉 weston-keyboard，触摸手机将无法输入。fcitx5-osk / kylin-virtual-keyboard 这类 OSK 依赖 KWin/合成器特性，在 Weston 上不可直接用。
3. **推荐主方案：在现有 weston-keyboard（它本来就是 IM）里加"拼音页 + 候选条"，配一张预编译小词典（MIT 数据）。** 无新守护进程、无 Qt、不动 Weston；预估 7–11 人日。候选质量=单字+常用词级别，够用且可演进。
4. **备选方案：Maliit 试飞（0.5–1 人日 spike）。** 若根分区有 ~400MiB 空余且实机流畅，可直接采用，几乎零开发。
5. **质量升级路径（二期）：** weston-keyboard 作 IM + 引擎侧车（fcitx5-rime 或 libpinyin，经 DBus/socket），候选条 UI 可复用方案 3 的代码；预估 8–14 人日。
6. **不要做：** squeekboard / wvkbd（Weston 缺 virtual-keyboard-v1、layer-shell）、ibus（无 Weston 集成路径）、plasma-keyboard（Qt/KWin 生态）、fcitx5 单独作 IM（无 OSK 槽位）。

## 1. 硬约束（决定一切的前提）

- **[验证]** Weston 14.0.2 / 15.0.1 都不支持 `zwp_text_input_v3`、`zwp_input_method_v2`、`zwp_virtual_keyboard_manager_v1`；只支持 `zwp_input_method_v1` + `zwp_input_panel_v1`（wayland.app 支持矩阵，Weston 列全部为 "x"，即未实现）。
  - https://wayland.app/protocols/input-method-unstable-v2
  - https://wayland.app/protocols/text-input-unstable-v3
  - https://wayland.app/protocols/virtual-keyboard-unstable-v1
- **[验证]** Weston 的 input-method v1：Compositor 侧在 `compositor/text-backend.c` 实现，含 `zwp_input_method_context_v1`（commit_string / preedit_string / preedit_cursor / delete_surrounding_text / keysym / grab_keyboard 等）。
  - 源码佐证：https://code.tokarch.uk/mainnika/weston/src/commit/23c8dc7b277062c3a7e0cf0ce7f8cdb28fb4fe29/compositor/text-backend.c
- **[验证]** **每个 seat 只能有一个 IM 客户端**：`bind_input_method()` 在第二次绑定时直接 `wl_resource_post_error("interface object already bound")`；且只允许 Weston 通过 `weston.ini [input-method] path=...` 启动的客户端绑定（`text_backend->input_method.client != client` 检查）。
- **[验证]** 因此 weston-keyboard 与 fcitx5 **不能同时工作**；Maliit 官方 issue 也确认"键盘必须由 compositor 启动"。
  - https://github.com/maliit/framework/issues/73
- **[验证]** input-method v1 没有 popup 协议（popup 是 v2 才有）：候选条必须画在键盘窗口内（或另开 panel surface），不能做跟随光标的浮层。这是中文 UX 的关键限制。
- **[验证]** Weston 的 IM 通过 `grab_keyboard` 保持应用焦点不被键盘点击抢走；任何"非 IM 的独立 OSK 窗口"在 Weston 上都会因点击而抢焦点、导致文本输入会话失效。**OSK 必须同时是 IM 客户端**。
- 已有补丁面：weston-keyboard（`clients/keyboard.c`，布局表+键盘绘制）与 weston-terminal（toytoolkit text-input-v1）均为我方源码树。

## 4. Q3 可行性方案与工作量（人日 = pd）

### 4a. 移植 Maliit 到 Weston v1 —— 现实，但体积大
- **[验证]** 协议匹配（v1 + inputpanel-shell QPA），Alpine 3.23 community 已打包 `maliit-keyboard 2.3.1`（aarch64，已链接 libpinyin）与 `maliit-framework 2.3.0`（含 `inputpanel-shell` QPA 插件源码，构建时依赖 qt5-qtwayland）。
- 集成方式：`weston.ini [input-method] path=/usr/local/bin/maliit-launcher.sh`；wrapper 导出 `QT_WAYLAND_SHELL_INTEGRATION=inputpanel-shell`、`QSG_RHI_BACKEND=software`、`QT_QUICK_BACKEND=software`，再 `exec maliit-keyboard -platform wayland`（issue #192 的实测配方）。
- 体积 [推断]：maliit-keyboard 103.9 + libpinyin 39.5 + Qt5（qtbase/qtdeclarative/quickcontrols2/qtwayland/qtmultimedia/qtfeedback）+ presage/anthy/hunspell/dconf ≈ **250–350 MiB**；rootfs 1.5GiB 镜像几近写满，需先 `df` 并可能重建镜像。
- 工作量：spike 0.5–1 pd；正式采用 2–4 pd（安装、配置、软渲染调优、回归）。
- 风险：中高。磁盘预算、Qt5 软件渲染性能、中文插件长期少维护（2021 后无中文相关提交）、会替换掉我方全部 OSK 补丁与布局。

### 4b. 给自补丁 weston-keyboard 加"拼音页 + 候选条"（推荐）
- 协议：完美，无需改动 Weston 或协议：预编辑 `preedit_string`，提交 `commit_string`，ASCII/控制键 `keysym`，删除 `delete_surrounding_text`/Backspace 回退。
- 需要写的代码（全部在 `clients/keyboard.c` 及新文件）：
  1. 离线词典生成器（Python，仓库内脚本）：pinyin-data(MIT) 单字 + 频率排序；可选 CC-CEDICT 词表；输出紧凑二进制（u16 音节索引 + UTF-16/UTF-8 字 + 频率档）。
  2. C 引擎：拼音串缓冲、**音节切分**（长音节优先 + 歧义回退，约 410 音节表的 DFA/trie）、单字与词候选合并排序、翻页、逐字选择后继续切分、空格/标点提交规则。
  3. 键盘 UI：`中/英` 切换键、候选条（一行 8–10 个，Pango 绘制，点击提交）、翻页键、拼音串显示（预编辑区）。
  4. 应用侧联调：确认 weston-terminal 的 toytoolkit 能显示 `preedit_string`；若不显示，加"OSK 内自绘拼音串"作为兜底（不依赖应用）。
- 工作量：词典 1–2 pd；引擎 3–4 pd；UI 2–3 pd；实机联调 1–2 pd → **7–11 pd**。
- 风险：中低。自包含、易回滚；质量上限=单字+常用词（无整句、无学习），可通过 4c 升级。
- 参考：数据 MIT；切分算法可参考 TinyPinyin（Java, 数据表法, Apache-2.0）与 pinyin2hanzi（Python, MIT）的思路，但不直接复用代码。

### 4c. 侧车引擎（weston-keyboard 保持 IM，工程质量更高）
- 架构：weston-keyboard（仍是唯一 IM，保住焦点/显隐/grab）把击键转发给一个后台引擎进程，拿回候选与提交串。引擎两种选择：
  - **fcitx5 DBus 前端**（`CreateInputContext` + `ProcessKeyEvent` + `UpdateClientSideUI`/`CommitString` 信号）：无需 fcitx5 绑定 input-method，避免单槽冲突；需要 DBus session（OpenRC 下手动 `dbus-daemon --session`）。
  - **libpinyin 直连**（C++，GPL-3.0）：进程内/旁路皆可，词典 39.5 MiB。
- 工作量：DBus/引擎胶水 3–5 pd + UI 2–3 pd + 打包/服务化 1–2 pd → **8–14 pd**。
- 风险：中。多一个守护进程与 DBus；fcitx5 客户端侧 UI API（`UpdateClientSideUI`）文档少；但换来整句/用户词库/模糊音等质量。

### 4d. 仅终端内的 CLI 拼音合成器（应急）
- 方案：TUI 读拼音、显示候选、选定后把 UTF-8 写回 tty（root 有 CAP_SYS_ADMIN，`TIOCSTI` 在 `dev.tty.legacy_tiocsti=0` 下仍可用；**[验证]** man7 TIOCSTI 说明）。
- 工作量 1–2 pd；UX 差（只服务终端、需自行启动、无预编辑），适合作为临时工具，不作为主方案。

### 4e. 换合成器（长期路线）
- 换 sway/phoc 等 wlroots 合成器 + fcitx5 + squeekboard/wvkbd：协议问题一次性消失，但要放弃 Weston 全套（面板终端、已验收的 bring-up、我方补丁），以周计，不在本期。

## 5. Q4 新版 Weston（15/16）是否补上 v2/v3？

- **[验证]** Weston 15.0.0 于 2026-02-19 发布（Vulkan renderer 实验性、Lua shell 等），发布说明未含 input-method 协议变更；wayland.app 对 **Weston 15.0.1** 的支持矩阵仍是：`text-input-v3 = 不支持`、`input-method-v2 = 不支持`、`virtual-keyboard-v1 = 不支持`。
  - https://lists.freedesktop.org/hyperkitty/list/wayland-devel@lists.freedesktop.org/thread/YQL735O53T5PUZT37T3ODCBVIHJMCVMG/
  - https://www.collabora.com/news-and-blog/news-and-events/weston-15-here-lua-shells-vulkan-rendering-smoother-display-stack.html
  - https://wayland.app/protocols/input-method-unstable-v2 （Weston 15.0.1 列为 x）
- **[验证]** 2019 年曾有补丁同时加 v3/v2 + virtual-keyboard + 内部 input-panel，但从未合并；现状仍以 v1 为准。
  - https://lists.freedesktop.org/archives/wayland-devel/2019-March/040333.html
- **[验证]** 同类需求在 2025-10 仍有厂商（NXP）在论坛提出，结论仍是"Weston 缺协议，要么改 Weston 内置键盘，要么换 wlroots"。
  - https://community.nxp.com/t5/i-MX-Graphics/Implementing-Better-On-Screen-Keyboard-Support-in-Weston-and/td-p/2183165
- **结论：未来 1–2 年不要把路线押在"Weston 上游补 v2/v3"上**；v1 生态（weston-keyboard / Maliit / fcitx5-v1）就是我们的能力边界。

## 6. Q5 中文键盘 UX 要点（实现清单）

- **候选条**：8–10 个候选、首选高亮、序号可选（点击直接提交）；v1 无 popup → 画在键盘窗口顶部一行或单独一行。
- **翻页**：专门的 `‹ ›` 键；同时支持 `,`/`.`（无候选时为标点）与 `-`/`=` 翻页（桌面惯例，可选）。
- **空格规则**：有候选 → 提交首选（含词组）；无候选 → 输出空格。**逗号/句号规则**：有候选 → 提交首选 + 输出 `，`/`。`；无候选 → 按半/全角设置输出 `,`/`。` 或 `.`/`。``。
- **回车**：清空拼音缓冲并提交原始 ASCII（escape）；**退格**：拼音非空先删缓冲末字符，缓冲空则 `keysym` Backspace（沿用现有回退设计）。
- **逐字选择**：点候选只提交该字（词），剩余拼音继续切分；这是 Maliit issue #39 的经典坑，必须按此语义实现。
- **切换**：`中/英` 键；`半/全角` 键（桌面惯例 Shift+Space，OSK 可单键循环）。
- **协议用法**：ASCII 字符/控制键/方向键用 `keysym`（保留终端与应用的 Ctrl/Alt 语义）；中文与中文标点用 `commit_string`；拼音缓冲用 `preedit_string`（带光标值）；删预编辑优先 `delete_surrounding_text`，失败回退 Backspace keysym。
- **渲染**：已装 wqy-zenhei（handoff Phase 1）；候选与预编辑用 Pango 即可，注意 45px 键宽下的字号与两行布局。
- **可选**：长按弹出备选、模糊音（z/zh、n/l）、缩拼；双拼不做。

## 8. 推荐与回退计划

**推荐（按顺序执行）**

1. **0.5–1 pd 决策性 spike：Maliit。** 前提先测 `df -h /`（需 ≥400MiB 可写空间）；若空间不足直接放弃 A。
   - `apk add maliit-keyboard`（自动带 maliit-framework、libpinyin、Qt5 组件）
   - 确认 `/usr/lib/qt5/plugins/wayland-shell-integration/libinputpanel-shell.so` 存在
   - wrapper + `weston.ini [input-method]`（环境变量见 §4a），用已补丁 weston-terminal 实测：拼音上屏、候选 ribbon、退格、切换语言
2. **主方案 B：给 weston-keyboard 加拼音页。** 先落地数据管线（pinyin-data MIT → 预编译表）与"OSK 内自绘拼音串 + 候选条"，再迭代切分与词表。里程碑建议：M-IME-1 = 单字输入可用；M-IME-2 = 常用词 + 标点规则 + 半/全角。
3. **质量升级 C（可选二期）**：引擎换成 fcitx5-rime（librime，BSD-3 代码 + LGPL-3 数据）走 DBus；UI 不变。若 fcitx5 打包链太脏，改直连 libpinyin。
4. **应急 D**：保留一个终端 CLI 合成器脚本，用于 SSH/调试场景（TIOCSTI 需 root）。

**明确不做**
- 不把 fcitx5 直接作为 Weston 的 `[input-method]`（会失去触摸键盘）。
- 不用 squeekboard/wvkbd/ibus/plasma-keyboard（协议或生态不匹配）。
- 不等 Weston 15/16 协议升级（[验证] 15.0.1 仍不支持）。

**验收建议（实机）**
- 输入 `nihao` → 候选首选"你好" 或"你"；点击候选正确上屏且拼音缓冲按逐字语义处理。
- `,`/`.` 在候选态提交首选并输出中文标点；空格提交首选；回车提交原始拼音。
- Backspace 先删拼音、后删文本；`中/英` 切换正确；候选条翻页可用。
- weston-terminal 中预编辑可见（否则启 OSK 自绘兜底）。
